## Google Colab运行

1. 将 T1_CPU完整复现.ipynb 上传到Colab。
2. 运行时选择 Python 3，硬件加速器选择“无”（CPU）。
3. 点击运行全部；出现按钮时上传原始 replication_package_MS-FTBDA-20-01585.zip。
4. 等五个分析阶段完成，查看报告与图；下载自动打包的结果ZIP。
5. 可选开启最后单元的Drive备份。当前会话内也可在文件面板找到输出ZIP手动下载。

Notebook已内嵌分析程序，不需要另传run_cpu.py。输入ZIP校验采用已审阅原包的SHA256，上传错文件时会停止。

本地已完整执行；另在本地模拟Colab上传/下载接口，执行了专用Notebook的全部代码单元，解压、全部分析、打包入口均通过。真实Colab上传、授权和下载需在用户浏览器操作，未声称已在远程Colab实际运行。默认按现有依赖运行并记录版本；需要一致环境时可打开首单元的PIN_TESTED_VERSIONS开关，安装后若提示重启则重启重跑。

## 本地运行

使用已经验证的Anaconda环境：

```powershell
& 'F:\anaconda3\python.exe' 'run_cpu.py'
```

程序默认使用同级上方的 replication_package_MS-FTBDA-20-01585 数据目录；在其他位置可显式指定：

```console
python run_cpu.py --data-dir /path/to/replication_package_MS-FTBDA-20-01585 --output-dir ./results
```

requirements_cpu.txt记录本次验证环境的精确版本。每次执行产生新的UTC时间戳目录，不覆盖之前结果。

## 已验证结果

已验证结果/CPU复现报告.md为阅读入口；CSV保留未四舍五入的数值，特别是很小的p值。报告包含实现差异与分析范围。已验证结果文件夹是本次成功运行的快照，重新执行的新结果在results目录。

- section4_original_costs.csv：作者第4节成本。
- section4_normal_formula_sensitivity.csv：仅Normal预测公式的对照。
- inventory_implementation_audit.csv：全部SKU、全部方法的原始库存实现审计。
- example_sku_inventory_trace.csv：一个多订单SKU的逐期核对表。
- field_means_author_convention.csv、field_post_ttests.csv：实地实验四组统计和实验后t检验。
- field_regression_author.csv：作者无截距回归。
- field_regression_intercept_HC3.csv：加入截距及HC3标准误的变体。
- field_did.csv：作者DiD复算、统一口径点估计；未认证的原始p值单独标记。
- field_measurement_sensitivity.csv：观察窗口与分母口径对照。
- matching_balance.csv、matching_summary.csv、matching_pairs.csv：匹配前后平衡与索引。
- matching_scores.png、matching_balance.png：匹配诊断图。
- input_audit.csv、id_audit.csv、run_metadata.json、三个.log：输入、身份映射限制、版本、源码哈希和原始执行日志。
